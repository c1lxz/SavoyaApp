# Контекст проекта: Мобильное приложение «Савоя» (Frontend MVP)

## 1. Цель
Разработать frontend MVP на React Native. Только клиентская часть: без backend, БД, реальной авторизации и Gate. Все данные — через заглушки. Задача: получить чистый интерфейс, рабочую навигацию и архитектуру, готовую к подключению реального backend.

## 2. Стек
- React Native (Expo разрешён)
- TypeScript
- React Navigation
- Zustand или Context API

## 3. Сценарии и экраны
1.  **Экран входа (`AuthScreen`):** Логин/пароль (демо: `demo`/`demo123`). Успех -> `HomeScreen`.
2.  **Главное меню (`HomeScreen`):** Пункты: «Создать пропуск», «Открыть шлагбаум», «Мои пропуски».
3.  **Создание пропуска (`CreatePassScreen`):**
    *   Поля: Номер авто, Номер участка, Дата окончания.
    *   Чекбокс «Постоянный пропуск» (отключает/делает необязательным поле даты).
    *   Кнопка «Создать». Пропуск добавляется в список.
4.  **Открыть шлагбаум (`OpenBarrierScreen`):** Кнопки «Въезд» и «Выезд». Показываем mock-результат (успех/ошибка).
5.  **Мои пропуски (`MyPassesScreen`):** Список созданных пропусков с отображением статуса (активен/истёк/постоянный). Пустое состояние.

## 4. Архитектура (Обязательно)
src/
app/

store/ # Zustand/Context
types/ # TypeScript типы
theme/ # Стили (тёмно-зелёный, светлый текст, природная стилистика)
assets/

text

## 5. Визуальный стиль (Макеты)
*   Тёмно-зелёная природная гамма.
*   Светлый текст, крупные элементы.
*   Полупрозрачные карточки, мягкие скругления.

## 6. Технические требования
*   Код строго типизирован (TypeScript).
*   Все вызовы идут через сервисный слой (никаких прямых моков в экранах).
*   Каждое действие имеет состояния: `idle`, `loading`, `success`, `error`.
*   Обязательные TODO-комментарии для будущей замены моков на API.

## 7. Запрещено
Реализовывать backend, API, интеграцию с Gate, БД, регистрацию, SMS, push-уведомления и любую другую серверную логику.
