# News validation matrix

The Node scenarios execute the production TypeScript services with mocked transport, storage, SDK calls and timers. They do not mount React screens or prove physical-device behavior. Use `npm run test:news`, `npm run test:notifications`, and `npm run typecheck` from `frontend`.

| ------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------- |

| Rejected POST, server failure, malformed success, timeout                 | Service distinguishes confirmed rejection from unknown delivery; timeout aborts request                                                                 | Root separately exercised offline publication in browser; pending draft stays locked for retry                   |

## Final performance changes

- Fullscreen list renders one item initially, one per batch, with a three-screen window. Only the selected photo uses the original URL; adjacent pages use thumbnails. Native images have explicit display dimensions and `resizeMethod="resize"`.
- Repeated rounded upload percentages no longer rebuild editor state. The synthetic 1000-event trace fell from1001callbacks to2callbacks, including completion.
- Autosave depends on author content and pending publication data, not volatile upload percentages. Explicit save-on-navigation and save-before-publication remain in place.

The callback reduction and media-source policy are measured service-level results. No FPS, network-throughput improvement, memory ceiling, successful live FCM delivery or physical-device performance is inferred from them.
