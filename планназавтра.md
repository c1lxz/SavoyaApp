# План доработки до MVP (на завтра)

## 1. Критичные исправления бэкенда (P0)
- Запретить создание пропуска с пустым `access_point_ids` (валидация схемы/роута, возврат `422`).
- Запретить логин неактивного пользователя (`is_active = false`) с корректной ошибкой `401/403`.
- Исправить логику отмены постоянного пропуска: деактивация ключа в Gate по бизнес-правилу.
- Добавить тесты на эти 3 кейса в `backend/tests`.

## 2. Валидация номеров ТС (P0-P1)
- Вынести нормализацию номера в единый модуль (front + backend): trim, upper, удаление лишних пробелов.
- Разрешить ввод русских букв в формате номера (например, `АВЕКМНОРСТУХ`), плюс цифры.
- Согласовать regex для фронта и бэка, чтобы не было расхождений.
- Если символы не поддерживаются Gate, делать мягкую нормализацию/транслитерацию на backend перед отправкой в Gate, а пользователю показывать понятную ошибку при невозможности преобразования.
- Добавить unit-тесты на валидные/невалидные номера, включая русские буквы.

## 3. Устойчивость фронтенда (P1)
- Обернуть `login/logout/restoreSession` и `openAction` в `try/catch`, выставлять состояние `error` без unhandled rejection.
- Нормализовать отображение ошибок API (когда `detail` — объект).
- Убрать проблемы с кодировкой сообщений.

## 4. Сессия и UX (P1)
- Сохранение токена в `SecureStore`/`AsyncStorage`.
- Автовосстановление сессии при старте приложения.
- Проверить сценарии: первый вход, перезапуск приложения, протухший токен.

## 5. Подготовка к тестам (обязательно перед релизом MVP)
- Зафиксировать окружения:
  - Python `3.12` для backend.
  - Node/Expo версии из проекта.
- Сделать `test.env` и чек-лист переменных (`DATABASE_URL`, `DEBUG`, `GATE_REAL_INTEGRATION_ENABLED`, `GATE_MDB_PATH`).
- Подготовить отдельную тестовую БД (SQLite для CI + Postgres smoke локально).
- Добавить команды в README/скрипты:
  - backend: `py -3.12 -m pytest -q backend/tests`
  - frontend: `npm run typecheck`
  - smoke API: логин -> создать пропуск -> открыть точку доступа
- Добавить минимальные фронтовые тесты (stores/services) и smoke e2e-сценарии.
- Подготовить шаблон bug report: шаги, expected/actual, окружение, логи.

## 6. Интеграция с Gate/config.mdb (P1-P2)
- Сначала создать `config.mdb`
- Проверить схему таблиц в `config.mdb` и документировать обязательные поля.
- Проверить ODBC-драйвер и доступ по `GATE_MDB_PATH`.
- Явно зафиксировать, что физическое открытие сейчас возвращает `integration_unavailable` до реализации transport-слоя.
- Добавить тесты на операции ключей/прав доступа без физического открытия.

## 7. Техдолг и стабилизация (P2)
- Перевести startup FastAPI на lifespan (убрать deprecated `on_event`).
- Привести строки/файлы к UTF-8.
- Добавить pre-commit проверки (typecheck + backend tests).

## Критерий готовности MVP
- Критичные backend-баги закрыты и покрыты тестами.
- Создание пропуска и открытие точек работает стабильно в реальном API-режиме.
- Номера ТС валидируются консистентно, включая русские буквы.
- Есть повторяемый прогон тестов и smoke-чеклист перед сборкой.
